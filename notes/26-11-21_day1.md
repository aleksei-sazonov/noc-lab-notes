# Конспект День 1 (21.11.2026) — Сборка NOC-стенда

**Тема:** Диагностика сети, файрволы, установка Node Exporter и Prometheus.

## 🛠️ 1. Диагностика сети и DNS (L3 / L7)
**Проблема:** После отключения VPN `curl` и `ping github.com` выдавали ошибку `Temporary failure in name resolution`.
**Диагностика:**
* `ping 8.8.8.8` — успешно (L3 работает, интернет есть).
* `cat /etc/resolv.conf` — показал `nameserver 127.0.0.53` (локальный stub).
* `resolvectl status` — показал, что отключенный VPN-интерфейс `Turkey` всё ещё пытается быть DNS-сервером (`10.254.254.254`).

**Решение:**
1. Очистили DNS у мертвого интерфейса: `sudo resolvectl dns Turkey ""`
2. Принудительно задали DNS для Wi-Fi: `sudo resolvectl dns wlp3s0 8.8.8.8`
3. Перезапустили службу: `sudo systemctl restart systemd-resolved`

## 🛡️ 2. Сетевой экран (UFW) (L4)
**Проблема:** Node Exporter работает локально, но с Mac (в браузере) не открывается (`time out`).
**Решение:**
* Проверили статус: `sudo ufw status verbose` (был active).
* Открыли порт для внешнего доступа: `sudo ufw allow 9100/tcp`
* Также открыли порт для Prometheus: `sudo ufw allow 9090/tcp`

## 📊 3. Установка Node Exporter (L4 / L7)
**Назначение:** Агент, который собирает метрики Linux (CPU, RAM, Диск) и отдает их по HTTP.
**Установка:**
1. Скачали архив: `curl -L -O https://github.com/prometheus/node_exporter/releases/download/v1.8.2/node_exporter-1.8.2.linux-amd64.tar.gz`
2. Распаковали: `tar -xvf node_exporter-1.8.2.linux-amd64.tar.gz`
3. Запустили в фоне: `nohup ./node_exporter &`

**Проверка:**
* `ss -tlnp | grep 9100` (порт слушается)
* `curl -I http://localhost:9100/metrics` (отдает HTTP 200 OK)

## 🧠 4. Установка Prometheus
**Назначение:** База данных временных рядов (TSDB), которая опрашивает (scrape) экспортеры и хранит метрики.
**Установка:**
1. Скачали архив: `curl -L -O https://github.com/prometheus/prometheus/releases/download/v2.54.1/prometheus-2.54.1.linux-amd64.tar.gz`
2. Распаковали: `tar -xvf prometheus-2.54.1.linux-amd64.tar.gz`
3. Настроили `prometheus.yml` (добавили таргет `localhost:9100`).
4. Запустили: `./prometheus --config.file=prometheus.yml > prometheus.log 2>&1 &`

**Проверка:**
* В браузере: `http://192.168.1.79:9090`
* Вкладка **Status -> Targets**: таргеты `node` и `prometheus` в статусе **UP** (зеленые).

## 💡 Шпаргалка по командам (Что выучить сегодня)

* `ip route get <IP>` — показать, через какой интерфейс пойдет трафик (L3).
* `resolvectl status` — диагностика DNS (L7).
* `ss -tlnp` — посмотреть, какие порты слушаются на сервере и какими процессами (L4).
* `curl -I <URL>` — проверить HTTP-ответ (только заголовки) (L7).
* `sudo ufw allow <порт>/tcp` — открыть порт в файрволе (L4).
* `pkill <имя_процесса>` — убить зависший процесс.
* `> file.log 2>&1 &` — запустить процесс в фоне и перенаправить весь вывод (и ошибки) в файл.

## ❗ Ошибки и как их решать (Твой NOC-опыт)
* **`broken pipe`** при `curl | head` — это нормально. `head` закрывает соединение, `curl` не успевает дописать данные.
* **`address already in use`** — порт уже занят другим процессом. Лечится через `ss -tlnp` (найти PID) и `kill` или `pkill`.
* **YAML-синтаксис Prometheus** — очень капризный к пробелам и дефисам. Ошибка `field not found` значит, что в названии параметра опечатка (например, пробел вместо `_`).
